Open-source key & randomness auditor

A horned guard for your keys.

keyceratops finds broken randomness in what your devices and servers already publish (public keys, certificates and signatures), points to the software behind it, and inventories what a quantum computer will break. It never needs a private key.

Version 1.0.0 · Python 3.10+ · MIT license

Three horns

A random number generator that fails rarely fails loudly. It leaves quiet traces in public data: repeated primes, repeated nonces, the same key on many devices. keyceratops reads those traces.

1

Find randomness failures

Checks keys, certificates and signatures for the fingerprints of a bad generator.

  • RSA keys sharing a prime (batch GCD)
  • ECDSA nonce reuse and bias
  • The same key on many devices
  • ROCA (Infineon) keys, broken RSA structure
  • Weak certificate serial numbers
  • SP 800-90B health tests for raw entropy
2

Point to the cause

Labels every host with its SSH software, firmware or device model and asks which label the affected hosts have in common.

  • SSH version banners from collect
  • Your own inventory CSV
  • Vendor names in self-signed certificates
  • Fisher exact test, Bonferroni-corrected
3

Plan the post-quantum move

Inventories every algorithm, its strength today and its exposure to a quantum computer.

  • RSA, ECDSA, EdDSA, ML-DSA, SLH-DSA, ML-KEM
  • Migration priorities (NIST IR 8547 deadlines)
  • Post-quantum key exchange on TLS and SSH
  • CycloneDX 1.6 CBOM export

What it catches

Each finding comes with what is wrong, what to do, and where it was seen. Keys appear by fingerprint only.

CheckSeverityWhat it means
shared-primeCRITICALTwo RSA keys share a prime factor: anyone can compute both private keys.
ecdsa-nonce-reuseCRITICALOne key signed twice with the same nonce: the private key follows by algebra.
duplicate-keyHIGH–CRITICALThe same key on several devices: a factory default or identical boot-time entropy.
rsa-rocaHIGH–CRITICALKey made by Infineon RSALib (CVE-2017-15361): factorable far below its nominal strength.
rsa-close-primes, rsa-small-factor, …CRITICALStructurally broken RSA moduli (Fermat-factorable, even, square, tiny).
ecdsa-shared-r, ecdsa-biased-nonceHIGHNonces repeated across keys, or implausibly short: generators that are not independent.
serial-*MEDIUM–HIGHCertificate serials too short, sequential or colliding (CA/B Forum Ballot 164).

Install

Python 3.10 or newer. A virtual environment keeps it apart from your system Python. Dependencies: cryptography and gmpy2.

From GitHub (recommended)

python3 -m venv .venv
. .venv/bin/activate
pip install "keyceratops @ git+https://github.com/otinzei/keyceratops"
keyceratops --version

From a downloaded release

Get the .whl file from the latest release, then:

pip install ./keyceratops-1.0.0-py3-none-any.whl

Source code: download ZIP.

Usage

Four commands: demo, scan, collect and entropy. Reports come in English or Japanese (--lang en|ja).

Try it on a synthetic fleet

Writes a fleet of certificates and keys with planted failures (the keys are deliberately insecure) and audits it.

keyceratops demo /tmp/fleet
keyceratops scan /tmp/fleet --sigs /tmp/fleet/signatures.jsonl

Audit files you already have

PEM and DER certificates, public keys and CSRs, OpenSSH known_hosts and authorized_keys, whole directories. Private keys are recognised and skipped unread.

keyceratops scan ~/.ssh/known_hosts /etc/ssl/certs
keyceratops scan certs/ -f md -o report.md       # Markdown report
keyceratops scan certs/ --fail-on high           # exit 1 on findings: a CI gate

Collect from your own servers

Gathers host keys, certificate chains and fresh ECDSA signatures from TLS and SSH servers into a snapshot. More samples make nonce problems visible.

keyceratops collect ssh://192.168.1.10 tls://nas.lan:8443 router.lan -n 20 -o lab.jsonl
keyceratops scan lab.jsonl

Find the cause

Add an inventory (host,vendor,model,firmware) and the report lists the labels that are over-represented among affected hosts.

keyceratops scan lab.jsonl --inventory devices.csv
Output
■ Leads (software / models over-represented among affected hosts)
    - SSH software dropbear 2014.63: 6 of 6 affected (others: 0 of 14)  p=0.0001 · unlikely to be chance
        [shared-prime]

Plan for post-quantum

See every algorithm in use, what breaks it, and what to replace first. Export a CycloneDX 1.6 CBOM for other tools.

keyceratops scan certs/ lab.jsonl --pqc
keyceratops scan certs/ lab.jsonl -f cbom -o cbom.json
Output
■ Post-quantum inventory
  9 key(s) (3 quantum-safe) · 6 certificate(s) · 4 endpoint(s) (1 with post-quantum key exchange)
    - ECDSA P-256: 3 / 128-bit / broken
    - ML-DSA-65: 1 / 192-bit / resistant (NIST category 3)
  Migration priorities:
    1. already broken (see findings above): 1
    3. quantum-vulnerable certificates valid past the end of 2030: 2
    4. endpoints without post-quantum key exchange (recorded traffic can be decrypted later): 3

Only scan what you own or are authorised to test. collect contacts exactly the targets you name, with no address-range expansion. It stops before authentication on SSH and before key exchange completes on TLS.

How it works

Every detection rests on a fact that holds for healthy keys with overwhelming probability. When it fails, the generator is to blame.

Shared primes

Independent RSA keys never share a prime. A product tree and remainder tree compute the GCD of every modulus with all others at once, so a hundred thousand keys take about a minute and a half.

Repeated nonces

An ECDSA signature is s = k⁻¹(z + r·d). Two signatures with the same k share r and give two equations in d. keyceratops reports this but never computes or prints the key.

Verified signatures

Signatures collected from TLS 1.2 handshakes and SSH key exchanges are checked against the server's key before their message hash is recorded, so the evidence is the server's own.

Post-quantum probes

To ask a TLS 1.3 server about X25519MLKEM768 it offers the group without a key share. A server that supports it must answer with a HelloRetryRequest naming it. No ML-KEM math is needed.

“No problems found” is not proof of soundness. keyceratops only sees failures that leave a trace in public data. A label in “Leads” is a place to look, not proof of a cause.
